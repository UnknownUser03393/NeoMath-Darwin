## 镜头 1：打开丢根 Demo（90 秒）

**操作**：点击 Demo 选择器，选择"丢根（lost-root）"。

**画面**：加载了 3 个 Cell 的 Notebook：

```
Cell 1: x(x-1) = 0      → 解集: {0, 1}
Cell 2: x-1 = 0          → 解集: {1}
```

**操作**：按 `Ctrl+Enter` 运行。

**画面**：
- Cell 1 → Cell 2 的箭头上出现醒目的 ❌ 不等价标记
- Cell 2 被标记为 **Root Fault**
- Witness 面板弹出：`x = 0`

**旁白**：
"运行后自动停在第一个可证明的错误处。`x(x-1)=0` 两边同时除以 `x`，得到 `x-1=0`。
这个操作看起来很合理——但系统立刻指出：**丢根了**。前一步解集是 `{0, 1}`，后一步只有 `{1}`。"

**操作**：鼠标悬停在 Witness `x=0` 上，显示代回结果。

**画面**：
```
代入 Cell 1: 0×(0-1) = 0  ✅ 成立
代入 Cell 2: 0-1 = -1 ≠ 0  ❌ 不成立
→ x=0 是原方程的解，但被丢失了
```

**旁白**：
"更关键的是，Witness 不是一个模糊的提示——它是一个精确值 `x=0`，你完全可以自己代回去验证。
0 在第一步 `0×(0-1)=0` 成立，在第二步 `0-1=-1≠0` 不成立。亲眼看到，不是 NeoMath 告诉你错了。"

---

## 镜头 2：为什么是这一步（60 秒）

**操作**：点击 Cell 2 的 Diagnostic 标签。

**画面**：展开诊断信息——
```
错误类型：丢根（ROOT_LOST）
丢失解：x = 0
原因：方程两边除以 x 时，默认 x ≠ 0，
      但 x=0 恰恰是原方程的一个解。
解决建议：不要除以 x，改为提取因式：
      x(x-1) = 0 → x = 0 or x = 1
[一键修复] 按钮
```

**操作**：点击一键修复。

**画面**：新 Cell 插入，解集恢复为 `{0, 1}`，等价标记变绿 ✅。

**旁白**：
"NeoMath 不仅指出错误，还告诉你**为什么错**和**怎么改**。
一键修复只是建议——你也可以自己编辑 Cell，再按 `Ctrl+Enter` 重跑。"

## 镜头 3：平方增根 Demo（90 秒）

**操作**：切换到"平方增根（extraneous-root）"Demo。

**画面**：
```
Cell 1: sqrt(x+5) = x-1    解集: {4}
Cell 2: x+5 = (x-1)²      解集: {1, 4}
```

**操作**：运行。

**画面**：
- ❌ 不等价
- Witness: `x = 1`
- 代回：`sqrt(1+5) = sqrt(6) ≠ 0 = 1-1`

**旁白**：
"这是一个更微妙的错误。`sqrt(x+5) = x-1` 两边平方得到 `x+5 = (x-1)²`，
解出来是 `{1, 4}`——但代回原方程，`x=1` 不成立。这是'增根'：平方操作是**单向蕴含**，不是等价变换。"

**操作**：在变量面板手动输入 `x = 4`，点击 Probe。

**画面**：
```
Probe x=4:
  Cell 1: sqrt(4+5) = sqrt(9) = 3, 4-1 = 3 ✅
  Cell 2: 4+5 = 9, (4-1)² = 9 ✅
```

**旁白**：
"你可以手动 Probe 任何值。`x=4` 在两步都成立——它不是增根。系统也会标明 `x=1` 是增根而非`x=4`。"

---

## 镜头 4：定义域扩大 Demo（60 秒）

**操作**：切换到"定义域扩大（domain-expansion）"Demo。

**画面**：
```
Cell 1: (x-1)/(x-1) = 1    定义域: ℝ \ {1}
Cell 2: 1 = 1               定义域: ℝ
```

**操作**：运行。

**画面**：
- ⚠️ 条件不等价（定义域扩大）
- Witness: `x = 1`

**旁白**：
"第三种常见错误：定义域扩大。`(x-1)/(x-1)=1` 化简成 `1=1` 看起来完全正确——但 `x=1` 在原式里分母为零，没有定义。
**在简化分式的时候，定义域被悄悄扩大了**。NeoMath 不仅追踪解集，还追踪定义域。这是常规代数训练容易忽略但数学上至关重要的一点。"

---

## 镜头 5：语义补全与证书（90 秒）

**操作**：切换到"语义补全（semantic-completion）"Demo。

**画面**：只有一个 Cell：`x²-4 = 0`

**操作**：选中 Cell，按 `Ctrl+Space`。

**画面**：CompletionBar 浮出——
```
[因式分解] (x-2)(x+2) = 0      ← 推荐
[展开]     x² - 4 = 0          ← 已是展开形式
[配方]     (x)² = 4            ←
```

**操作**：选择"因式分解"。

**画面**：
- 新 Cell 插入：`(x-2)(x+2) = 0`
- 变换证书弹出：
  ```
  变换：因式分解（FACTOR）
  模式：差平方（Difference of Squares）
  验证：✅ 已验证（解集保持：{-2, 2} → {-2, 2}）
  + 定义域保持：ℝ → ℝ
  ```

**旁白**：
"补全不是字符串模板——是 C++ 分析了 `x²-4` 的多项式结构后，识别出差平方模式 `a²-b²=(a-b)(a+b)`。
每个补全都附带**变换证书**，明确这个操作是什么、改变了什么、保持了什么。
它不是 AI 的模糊建议，是数学上可验证的操作。"

---

## 镜头 6：AI 的角色（60 秒）

**操作**：点击 Cell 的 Explain 标签，展示解释内容。

**画面**（本地模板）：
```
诊断：方程两边同时除以 x 导致丢根
解释：x(x-1)=0 → x-1=0 要求 x≠0，
      但 0 恰恰是方程的一个解。
      正确的做法是提取因式而不是除法。
```

**操作**：切换到 AI 解释（如已配置）。

**画面**（AI 改写）：
```
嘿！这里有个常见的坑 👀
你把等式两边同时除以 x 了，
但别忘了——除以一个数之前，
得先确认它是不是零！
x=0 恰好让原方程成立，
所以这一步悄悄把 0 这个解丢掉了。
下次记得先提取因式哦！
```

**旁白**：
"两种解释说的**数学事实完全一样**——区别仅在于措辞语气。
这是 NeoMath 对 AI 的核心原则：**AI 可以改写表达方式，但绝不碰数学真值**。
解集、定义域、等价判定、Witness——全部由本地 C++ 内核计算。
AI 只改变'怎么告诉学生'，不改变'告诉学生什么'。"

## 镜头 7：Replay 与验证报告（60 秒）

**操作**：回到丢根 Demo，修改 Cell 2 为正确结果。

**画面**：
- 修改 Cell 2：`x-1 = 0` → `x = 0 or x = 1`
- 等价标记变化：❌ → ✅
- 底部显示："Replay: 1/3 cached, 2 recomputed"

**旁白**：
"修改一行后，NeoMath 只重算受影响的后缀——前面不变的状态从缓存复用。
对于 200 步的文档，改最后一步，**P50 加速约 2.16 倍**。"

**操作**：如果不展示验证，切换到终端跑一遍：

```bat
cd desktop

python -m pytest tests/golden -q  # 14 golden cases

```

**旁白**：
"最后，NeoMath 的所有数学结论都经过独立验证：258 个 pytest 用例、14 个 golden case、
**10,000 组 SymPy 对照零差异**。不是一个 demo 跑得漂亮就交差的玩具。"

## 镜头 8：闭环总结（30 秒）

**画面**：回到 NeoMath 主界面，循环动画展示工作流：

```
Write ──► Complete ──► Run ──► Break ──► Explain ──► Fix ──► Replay
```

**旁白**：
"这就是 NeoMath：把数学推导当成可运行的程序——
写 → 补全 → 运行 → 停在第一个错误 → 给出亲手可验证的精确反例 → 修复 → 增量重放。
它不是代替学生思考，而是让学生的每一步思考都**可验证、可质疑、可修正**。

谢谢。"
